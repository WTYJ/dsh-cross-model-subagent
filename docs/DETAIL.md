# 模型分工

让普通 `subagent` 使用与主 agent 不同的模型执行任务：主 agent 负责规划、下达任务与审查，执行模型按规划完成具体工作。

侧边栏「模型分工」设置页提供：

- 全局默认执行模型。
- 已有会话的单模型覆盖，可选择继承全局、沿用父模型或指定模型。
- 新根会话自动开启 Agent Teams。
- 显示所选会话已保存的模型设置和下一次普通委派的生效状态。已有会话的 Agent Teams 开关位于对应根会话的官方模型／推理菜单。
- 真实刷新模型目录、会话列表和配置；保存被拒绝时保留草稿并显示错误。
- 「版本与更新」：显示当前与最新版本，检查后可一键安装新版本；新版本由 DSH 插件管理器安装，失败会自动回滚，需要重启时页面会说明。

本地链接安装（`link:`/路径）无法原地升级，页面会给出一次性的迁移命令；迁移到 Git 安装后即可使用页内一键更新。

会话默认值在每次普通 `subagent` 委派时读取，保存后影响下一次委派；已经运行的子代理不变。全局默认关闭时，会话仍可单独指定执行模型。旧版授权名单不自动转换，请重新选择默认执行模型。

本插件复用 DSH 官方委派工具，保留原生路由预检和子代理生命周期。支持内置 standard / ptc / cordis 的普通 spawn 委派；不覆盖自定义预设或自定义委派后端。`subagent_fork` 保持原生父模型和上下文继承行为，适用于审查。

默认模型与显式模型授权是两个独立机制。未填写 provider/model 时使用用户配置的默认；显式指定模型仍受 DSH 原生会话授权约束。本插件不修改已记录的授权策略，也不改主agent模型。

提供状态及配置工具，可查看默认模型与实际挂载状态。主agent收到执行子代理的结果后，仍应审查修改和检查证据。
